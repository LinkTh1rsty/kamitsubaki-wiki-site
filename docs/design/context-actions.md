# 界面操作与接口状态

适用范围：百科阅读器、文章、目录、贡献、账号、图库、编辑器，以及私有审核工作台。以本站黑白灰排版、细线和克制反馈为基线；词条背景和主题色继续由阅读器控制。

## 先判断链接的职责

| 内容 | 应用方式 |
| --- | --- |
| 正文中的词条链接、来源、引用 | 保持自然文本链接，不包成按钮。 |
| 面包屑、文档目录、同级导航 | 用对应导航/列表组件，明确当前位置。 |
| 完善词条、投稿、上传、查看审核、失败重试 | 用 `ContextAction`、`WorkspaceButton` 或同级审核后台按钮样式；不能只插入裸 `<a>` 或把接口返回值直接拼在按钮旁边。 |
| 加载、无结果、错误、成功 | 文字说明、状态标记与下一步动作分开。状态使用原位置的 `role=status`，不要与导航链接混排。 |

阅读器正文附近使用 `ContextAction`：`tone=secondary` 为主要的上下文操作，`quiet` 为相关指南，`layout=row` 用于侧栏的整行入口。页面标题操作仍使用 `WorkspaceButton`；每个操作区最多一个 `primary`。接口加载后由脚本生成的操作使用 `createContextAction`，保留真实 `<a href>` / `<button>` 语义。私有审核台使用自己的 `.button` 体系和相同的主次层级，不复制前端 Astro 组件。

统一状态：38px 桌面操作高度，触屏至少 44px；焦点有独立轮廓；悬停只改变背景、线条和箭头的小位移，不移动容器；减少动态效果时停止位移。明暗主题使用变量，不能在公共操作里硬编码 `text-white`、彩色按钮或独立光效。只有获得真实结果后才显示“可上传”“已提交”等状态，不能把暂存、审核通过、公开合并为一个成功状态。

## 已核对的入口

- 阅读器：完善度、待补全提示、正文结尾、相关文章、贡献者记录及失败重试。
- 目录与功能页：百科空筛选、文章阅读操作、图库标题、接口失败提示和无资料状态。
- 投稿与账号：投稿指引、审核回执、创作者详情/本机草稿、编辑器载入失败重试、上传服务额度信息。
- 审核后台：词条 GitHub 审核入口、审核决定与接口反馈。

开发时先检查是不是**操作**，再选组件；不要用 `innerHTML` 直接拼未经转义的接口内容。新增投稿入口后运行 `pnpm check:ui-actions`、类型检查与构建，并实际查看阅读器、相应投稿页、深浅色和窄屏。该静态检查只拦截可识别的裸投稿链接；动态 DOM、真实状态和视觉仍需人工验收。
