# 图片与缩略图

上传、原图路径和目录分类见[图片与文件教程](manuals/contribute/entry/zh.md)。上传不会压缩、缩放或重新编码原图；下述处理只生成独立展示副本。

本地图片继续放在 `public/images/`，词条中的 `image` 仍填写原图路径。原图不会被覆盖。

启动开发服务、检查或构建时，Astro 集成会自动生成 96、192、480、960 像素宽的 WebP。开发服务也会监听图片的新增、替换和删除。小图不放大，保留比例与透明度，自动修正 EXIF 方向；动画或无法解析的文件保留原图并在生成日志中说明。

可单独运行 `pnpm images:generate`。内容哈希和转换参数决定文件名；未变化的图片复用已有结果，替换原图后自动使用新 URL。`public/thumbnails/` 和 `.cache/image-thumbnails/` 是可再生成的输出，不提交到 Git。首次构建需要处理所有图片，后续本地构建会命中缓存。

组件使用 `ResponsiveImage`，并填写实际显示尺寸：

```astro
<ResponsiveImage src={song.image} widths={[96, 192]} sizes="80px" alt="" />
```

卡片使用 192 / 480 / 960 的响应式候选，列表小封面使用 96 / 192，详情封面使用更大的候选。浏览器按视口和屏幕像素密度选择，不把全站清单打进客户端脚本。首页随机换曲和 LABs 的 JSON 目录也输出缩略图，不能在客户端再换回原图 URL。

首页艺人背景在悬停或键盘选中时加载 960 像素版本，加载完成后淡入，不再预加载整份艺人列表。

`public/_headers` 为带内容哈希的缩略图设置一年 immutable 缓存，随 Cloudflare Pages 静态部署生效。开发服务的缓存响应头与线上不同。外部图片、SVG、游戏精灵图和正文原图不经过此流水线；新卡片请使用组件，避免重新出现缩小显示却下载原图的情况。
