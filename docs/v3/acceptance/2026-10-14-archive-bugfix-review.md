# 2026-10-14 代码 review 与并发修复

Review 基线为 `197f1df1`，重点检查新增归档工作区、社区服务和 Radio 的权限、账号隔离、并发状态与页面生命周期。本批是 PR 候选修复，尚未正式发布。

## 修复结果

| 优先级 | 问题与触发条件 | 修复行为 |
|---|---|---|
| P1 | 审核者使用集合 ID 可以读取作者未提交审核的私人草稿 | 审核权限仅允许读取待审核展览，私人草稿仍限作者 |
| P1 | 集合、任务、账号重新载入或房间请求跨越退出／账号切换，旧响应可能恢复旧界面或写入错误账号的本地记录 | 请求绑定预期账号；提交结果前核对账号代次、请求顺序及房间身份，丢弃已过期结果 |
| P2 | 单个公开集合链接要求登录，并返回账号／审核者内部 ID | 已公开集合允许匿名阅读，响应仅包含公开字段 |
| P2 | JSON `null` 或集合中的空项目触发内部异常和 500 | 请求体和集合项目验证返回 400 |
| P2 | 主持更新等待资料验证期间，房间已结束，旧更新仍返回成功 | 数据库更新同时检查房间仍未结束，迟到更新返回冲突 |
| P2 | 较早发出的房间参与刷新覆盖主持人的较新位置；离开或结束房间后 iframe 留在 DOM | 按修订版本拒绝旧位置；清理跟随 iframe 和位置缓存 |
| P2 | 首次身份检查完成的通知被当成账号切换，过期保护误取消正常加入 | 先等待身份检查完成，再绑定当前账号与房间请求；保留切换后旧响应不能恢复房间的检查 |
| P2 | Radio 保存播放进度时覆盖另一窗口刚修改的队列 | 从最新队列保存进度，仅更新仍在播放的曲目 |
| P2 | 同一首歌重新播放后，已销毁播放器的结束回调仍推进队列 | 播放器回调同时校验当前播放代次与曲目 |
| P2 | 浏览器从缓存恢复页面后，Radio 的进度定时器没有恢复 | 恢复页面时重启单个定时器并读取最新队列 |
