# 首页刷新时工具栏跳位修复

2026-09-19，本地 V3。

## 原因与改动

- 公告按钮原先在首页正文输出，采用旧版固定竖排位置，DOMContentLoaded 后才被 quietChrome 搬进工具菜单。现通过 BaseLayout 的 tools 插槽直接在工具菜单中输出；按钮标题也在服务端输出，取消运行时搬移和补文字。
- 关闭的工具菜单明确使用 display:none，固定定位的内部组件不参与首屏显示。
- 首页目录的未展开条目放入惰性 template，每次展开只将 12 条加入活动 DOM；背景切换改为委托监听，新增条目同样可使用原背景效果。保留展开、收起动画。
- 入场动画保留，但结束后不再等待 window.load（远程图片等非必要资源）。

## 验证边界

本地静态构建与浏览器交互验证；不代表线上已部署，也不作未测量的毫秒性能承诺。

本轮结果：18889 页构建成功。五种语言静态 HTML 检查通过：公告按钮在 tools-dock__menu 内，活动 artist-row 105 条、惰性模板内 1750 条。IAB 重复刷新、工具菜单打开/关闭、390px 宽度刷新与菜单打开通过；歌曲目录 12→24→36、收起和键盘重新展开通过。未进行网络节流和逐帧性能追踪，不能据此声称所有网络环境下零卡顿。

## 后续修正：恢复旧版首屏流程

用户反馈前次修复仍会出现滚动条先出现、组件延后和画面抽动，因此前次浏览器检查不能视为完整首屏验收。现恢复开发前的阻塞字体样式加载与短加载过渡；只有实际存在原生 viewTransition 才绕过过渡层。固定工具组件提前到正文之前输出，has-js 在首屏前设置，避免正文先显示再隐藏。根元素预留滚动条占位，弹窗锁定不再重复补偿已预留的宽度。
