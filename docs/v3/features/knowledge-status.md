# Knowledge Status｜资料完整度与缺项看板说明

资料完整度系统把“还缺什么”变成可见的字段状态。阅读器展示当前词条的完成情况，缺项看板汇总需要补充的档案，并提供对应的编辑入口，方便贡献者选择自己能核对的资料。

入口：`/zh/contribute/missing/`。相关实体阅读器有完整度摘要；`/zh/missing-data.json` 提供同一规则产生的页面数据索引。

## 已完成的功能

- 根据实体类型检查相应字段，展示加权完整度和缺项。
- 按关键词、实体类型、缺失字段组合筛选，支持缺项数、分数或标题排序。
- 首次显示 24 条，可继续分批展开，显示缺失字段统计。
- 地址保存筛选，支持清除条件、分享与浏览器前后退恢复。
- 使用真实源文件路径进入现有编辑流程，译文回退与元数据缺项分别展示。
- 阅读器、看板与 JSON 索引共用规则，避免同一词条出现不同评分标准。

## 使用方法

1. 在看板选择想贡献的内容类型，例如歌曲。
2. 选择自己能查证的字段，例如制作署名、来源或发行日期。
3. 打开词条核对已有正文与资料，确认缺项是否需要补到结构化字段。
4. 从编辑入口填写信息及来源，按既有贡献流程提交审核。
5. 内容公开并重新构建后，看板与阅读器更新状态。

示例：

```text
/zh/contribute/missing/?type=work-track&field=credits
/zh/contribute/missing/?type=live-event&field=setlist
```

第一条筛选缺少结构化制作署名的歌曲；第二条筛选需要 Setlist 却未填写的演出。一般活动与展览不会因没有曲目被当作此类缺项。

## 当前评分规则

分数为 0–100，根据适用字段的权重计算填写比例。

| 适用对象 | 检查字段及权重 |
| --- | --- |
| 所有实体 | 简介 2、结构化来源 2、图片 1 |
| 人物／虚拟艺人／团体 | 角色 2、活动起始日期 1、官方链接 1 |
| 歌曲 | 演唱者 2、制作署名 2、发行日期 1、歌词来源 1 |
| 发行 | 曲目 2、发行日期 1、主要艺人 1 |
| 活动 | 起始日期 1、场地名称 1、主要出演者 1 |
| 演唱会类型活动 | 额外检查 Setlist 2 |

空值、空白文字和空数组属于未填写，已知占位图片不计作有效图片。译文回退单独提示，权重为零，不影响元数据分数；自动派生的繁体中文不被当作缺少独立译文。

完整度表示字段填写情况，不等于事实正确率、来源可信度、档案质量等级或贡献者完成任务的比例。填满字段仍需要核对准确性和出处。

## 怎样理解缺项

看板检查结构化字段：缺少 `sources` 不一定表示正文没有引用，缺少 `lyricsSources` 也不一定表示正文没有歌词。贡献时应先核对正文，再按当前资料规则补充明确的出处与字段，避免重复劳动。

关键词可以查名称、别名、ID 及已知演唱者／创作者名称；筛选和统计随档案构建更新。没有足够资料时仍需检索可靠来源，不能为了提高分数填入推测。

编辑入口使用实际存在的内容路径；缺少独立译文时指向可维护的原资料。繁体中文沿对应中文源文件维护。资料填写不会绕过审核自动公开。

## 当前限制与维护入口

本轮完成缺项展示和贡献入口，没有新增任务认领、协作锁定、积分、排行榜或成就。数据索引用于当前页面，不是带稳定版本承诺的开放 API。

调整评分规则时应同时检查阅读器、看板和索引；新增实体类型先确认哪些字段适用，避免给展览、组织等对象布置不合理任务。
