## 常用操作

**研究一首歌曲：** Music 筛选作品，展开详情查看版本方向、来源、收录发行及演唱历史；跳到 Credits 查共同制作，再到 Statistics 查看筛选范围内的统计。研究下载附快照和引用；统计的 CSV 提供年度行，ZIP 同时保留报告和档案行。

**比较两场演出：** Live Mode 的“比较演出曲目”中每行输入一个演出 ID，最多四个。矩阵单元格是该歌曲在已记录曲目中的条目数。零值表示没有明确连接记录，不表示从未演唱；部分摘录会保留状态和未连接条目数。链接的 `lives` 参数可复现。

**做一份私人导览：** Collections 填标题、实体 ID 与逐行笔记，可通过选材控件添加章节，拖动或使用前后移动按钮排序。原始文本中空白行不会使笔记错位。保存设备草稿后可关闭再恢复，阅读预览可翻章、标记已读并续读。导出文件保留私人笔记，仅在主动导入时读取；导入不会赋予审核或公开状态。每个账号／访客最多 50 份草稿，达到上限时拒绝新建并提示失败，保留已有草稿。可删除不需要的草稿后重试。

**下载开放数据：** Open Data 选择当前或已保存快照、选择资料集合、核对哈希，再下载。JSON／CSV 对应所选集合；ZIP 包含完整公开快照、实体表、关系表、引用与权利说明。ZIP 不包含图片／音频文件、个人记录、设备草稿或社区审核身份。CSV 对公式文本做转义，零和数值负数保留。具体契约见 [Open Data v1](open-data.md)。

**记录巡礼：** Atlas 添加地点到私人路线并排序，再下载 GPX 或 GeoJSON。GPX 只含已核对真实坐标；GeoJSON 还保留缺坐标的真实地点。两者表示选择的站点顺序，不提供道路规划。

## 开源复用与维护

新增 [SortableJS 1.15.7（MIT）](https://github.com/SortableJS/Sortable) 处理触摸／鼠标章节排序，保留键盘按钮；减少动画偏好下禁用排序动画。新增 [fflate 0.8.3（MIT）](https://github.com/101arrowz/fflate) 在浏览器生成 ZIP，按需加载，不引入上传服务。继续复用 Leaflet 地图、PhotoSwipe 图片查看、现有 Lucide 图标和扫码模块。新增依赖锁定版本，完整许可已追加到 `public/third-party-notices.txt`。

设备草稿、阅读进度与观测站记录使用不同存储键。草稿按访客／账号隔离，账号切换、离页及延迟导入使用代际检查，避免旧请求把私人内容写入当前账号。私人预览不是发布；账号同步、公开集合、展览审核沿用共享服务的权限和并发规则。

公开资料是内容快照，旧哈希文件保持不变。维护者用 `pnpm archive:snapshot` 保存资料版本，并用 `pnpm archive:snapshots:check` 核对；历史目录展示当前构建和已提交快照。代码能力变化不自动制造新资料版本，也不把请求时间当作内容版本。

## 完成边界与资料缺口

十二项制作范围已补齐；历史资料覆盖持续维护。当前快照有 1,836 个实体、1,557 首歌曲、518 条时间轴事件；154 首歌曲有非空制作署名。12 条活动中 1 场有明确标注的部分 Setlist（7 个 BD 歌曲章节），1 条显式版本关系，1 个核对坐标、8 个虚拟地点，1 份明确日期视觉使用记录、25 条字段证据。BPM 与条码仍无实际录入。此批没有虚构或批量推断这些资料。

前台、权限模型和本地执行环境的回归可以验证代码流程。实际账号同步、真实投稿／独立审核、多人在线、真实相机与第三方播放器仍须正常账号和相应服务验收。本次没有合并或发布到正式站点，发布继续使用已有守卫。具体测试与浏览器结果见 [本轮验收](../acceptance/2026-10-14-f01-f12-completion.md)。
