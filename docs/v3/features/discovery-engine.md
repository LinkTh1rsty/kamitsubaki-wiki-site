# Discovery Engine｜推荐与每日探索说明

Discovery Engine 根据用户主动选择的艺人、作品类型、风格和年份，从已有元数据与明确关联中提供推荐，并生成可以逐站阅读的每日探索路线。它适合“已经有一个兴趣点，但不知道下一步看什么”的使用场景。

入口：`/zh/explore/discovery/`。首页、探索目录和相关词条提供入口；Story Mode 完成后也可进入。

## 已完成的功能

- 最多选择三位艺人／创作者，或指定一个档案作为起点。
- 组合内容类型、已填写的风格／标签、关键词、年份及范围，可选择加入 Chronicle。
- 推荐展示连接依据；初次显示 12 项，可以继续分批展开。
- 每日路线提供三、五、七站选项，可换一条路线、上一站／下一站或从当前档案继续。
- 地址保存已应用偏好、路线日期、变体和当前站点，支持分享、语言切换与历史恢复。
- 数据加载失败可重试；没有脚本时仍有构建时的初始推荐与路线内容。

## 使用方法

1. 打开偏好设置，选择喜欢的艺人，或填入具体档案起点。
2. 选择内容类型、年份等条件并应用，查看推荐及每项依据。
3. 开始每日路线，逐站打开资料；觉得路线不合适时换一条。
4. 希望别人看到同一条路线时，用分享入口复制固定日期的地址。

示例：

```text
/zh/explore/discovery/?artist=kaf&year=2020
/zh/explore/discovery/?artist=kaf&year=2020&day=2026-10-13&length=5
```

年份默认范围为前后两年，可改成严格匹配或前后五年。第一条随每日日期更新，第二条固定路线日期；同一数据版本、偏好、日期和变体可以复现路线。

## 推荐依据

艺人偏好使用直接或两步的明确连接，多位艺人表示候选可以连接到其中任意一位，不要求同时与全部艺人相连。关系解释保留原方向、署名角色、日期和来源入口。

风格与标签只使用对应档案已填写的数据，不将艺人标签自动继承给其歌曲。关键词搜索既有名称、别名、署名与收录描述；不会从歌词或声音自动推断“抒情”“治愈”等情绪标签。未知日期不被猜成指定年份，跨年活动按已记录范围匹配。

推荐不使用账号收藏、私人浏览历史或后台个人画像。它提供有据可查的档案探索，当前没有加入 AI 对歌曲风格的自动分类。

## 每日路线与分享

默认日期按 UTC 更新，香港时间约在每天 08:00 进入新的 UTC 日期。分享会固定日期，因此不会随第二天自动换路线。

路线先选符合偏好的起点，后续沿真实关联前进，允许跨内容类型和年份；后续站点不保证全部符合初始过滤条件。路线不重复节点，资料不足时只展示能成立的长度；孤立节点可以只有一站。

“换一条”改变已应用条件下的路线变体，不新增事实连接，也不应用尚未提交的表单修改。站点导航同样保留这些修改，用户需主动应用新条件。档案数据更新后，即便地址不变，路线也可能改变，因为分享没有锁定历史数据版本。

Story Mode 使用编辑编排的学习目标与固定章节；Discovery 使用当前兴趣与明确关系生成开放探索路线。两者可以相互衔接。

## 当前覆盖与限制

歌曲风格字段覆盖仍很少，严格风格筛选可能没有结果。界面提供放宽条件入口，不会自动补标签来制造结果。

公开文章只收录匿名公开列表中的标题、简介、记录日期和有效关联 ID，不复制全文、账号或非公开内容。文章连接同样不靠标题猜测；公开索引不完整时保留其他档案推荐并提示。阅读文章继续使用既有阅读入口。

## 维护入口

扩充推荐质量主要靠补充有来源的日期、署名、标签和明确关联。更新后重新构建，检查空结果、推荐依据、每日日期变化、分享复现、不同语言以及资料加载失败状态。
