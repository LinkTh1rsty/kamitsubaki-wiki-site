# Graph｜全站关系图谱说明

Graph 把人物、团体、歌曲、发行、演出、创作者和可选时间轴事件放在同一张关系网络中。每条连线对应已有档案中的明确关系，用户可以从一个名字继续探索，也可以查询两个实体之间的连接路径。

入口：`/zh/graph/`。主导航、首页探索和实体阅读器都有入口；旧的 `/zh/explore/relations/` 关联页保留，可带着查询进入 Graph。其他语言替换路径中的 `zh` 即可。

## 已完成的功能

- 全站画布包含有关系与暂时没有关系的实体，可选择是否加入 Chronicle 事件。
- 按实体类型、关系类型筛选；在全图与某个节点的一至三层周边之间切换。
- 搜索定位节点，节点目录可用键盘访问；详情展示档案入口和连接依据。
- 平移、缩放、拖动节点、适配当前图形，以及导出当前图像为 PNG。
- 指定起点与终点，比较最多三条较短的、没有重复节点的连接路径。
- 地址保存筛选、中心节点及查询端点，可复制分享、切换语言和用浏览器前后退恢复。

## 使用方法

1. 打开 Graph，在搜索框输入人物、作品名称或别名。
2. 在结果或节点目录选择对象，查看详情和已有连线。
3. 初次探索建议切到“周边”，先看一层，再增加到两层或三层。
4. 如要回答“花谱与理芽有哪些连接”，设置两个查询端点，查看各条路径的每一步依据。
5. 用分享入口复制地址；需要展示当前图形时导出 PNG。

| 操作 | 效果 |
| --- | --- |
| 拖动画布空白处 | 平移视图 |
| 拖动节点 | 调整当前布局中的位置 |
| 滚轮或触控缩放 | 放大、缩小图形 |
| 适配视图 | 将当前图形放进可见范围 |
| 搜索 | 定位节点，保留其余图形 |
| 类型／关系／事件筛选 | 改变参与显示与路径查询的数据范围 |

示例地址：

```text
/zh/graph/?entry=kaf&scope=neighborhood&depth=2
/zh/graph/?from=kaf&to=rim
```

第一个查看花谱两层周边，第二个设置花谱与理芽为路径端点。查询结果随档案资料更新而变化。

## 怎样理解连线与路径

连线来自明确记录的所属、成员、演唱、制作署名、发行曲目、出演或一般关联；选入的 Chronicle 事件则使用已记录的实体引用。相同实体按稳定 ID 统一，悬空引用不会生成新节点，不同署名角色等有效差异仍保留。

查询允许沿连接探索，同时展示原记录的方向、角色、日期精度和依据入口。比如“歌曲 → 作曲者”和“歌曲 → 演唱者”是两种关系，不能把它们直接解释为两个人的私人关系。

路径优先按连接步数寻找，至多展示三条较短候选；这是有界查询，不保证穷举所有可能路径。实体类型、关系类型和事件开关会影响查询；只看局部周边不会把查询限制在局部画面中。没有符合条件的路径时，应调整筛选或补充有依据的资料。

## 分享与当前限制

分享地址保存查询条件，不保存手动拖动后的节点坐标、缩放状态或 PNG。布局位置属于当前会话，重新打开时可能重新排布。PNG 是图像文件，不能继续交互。

Graph 表达档案已记录的连接，不评估关系强弱，不推断缺失事实。时间轴事件是可选节点，不能加进百科实体数后当成新增词条数量；没有连线的实体也不等于“实际上没有关系”。

## 维护入口

新关系应写入相应词条的结构化字段或 Chronicle 引用，不在图形界面写死特定人物。更新后校验引用是否存在，并检查两端节点、文字依据和路径查询。
