# 功能数据与关联维护

## 统一实体身份

`id` 是跨语言、跨文件和关联的稳定键。显示名称与磁盘路径可以变化，既有 ID 不随之改变。实体来源是 `src/content/`，共享字段校验由 `src/lib/entitySchema.mjs` 执行，路由与关系由 `entityModel.mjs`、`entityRegistry.mjs` 解析。

## 分类与主页

依据详细地图维护 `src/data/classification-map.json`。人物在明确的组别节点出现，不因为兼任身份自动改到个人层级。地图未编目的内容不应随意塞入已审核分组。目录调整使用 `node scripts/v3/organize-content.mjs` 预演，确认后 `--apply`，再检查编辑器路径同步。

## 时间轴与足迹

事件保存在 `src/data/chronicle/`，纪元区间在 `src/data/taxonomy/eras.yml`。填写事件日期、实体关联和来源，日期驱动纪元归属；词条中的普通日期或正文段落不会自动变成时间轴事件。关联 ID 必须存在，跨语言事件共用事件身份。运行 `pnpm validate:content` 检查事件与引用，再在时间轴和相应实体阅读器查看足迹。

## 形态、署名与反向关联

`presentation.morphing` 指定同一形态组、槽位和顺序。`performers` 表示表演者，`credits` 表示署名，`relations` 表示一般实体关系，`affiliations` 表示所属。使用结构字段建立关联，不在模板写死某个艺人 ID。正向字段经过实体索引生成反向入口；添加关系后检查两端阅读器。

## 关系路径与资料完善看板

关联网络的“起点／终点”查询使用同一实体目录中的显式关系，按连接步数查找最短路径。每一步保留原始关系方向、署名角色和依据链接；同长路径稳定排序，悬空引用不参与查询。时间轴事件由用户显式选择是否纳入，不据此推断私人关系或关系强弱。查询保存在地址的 `from`、`to` 与可选 `events=1` 参数中，可分享或用浏览器前后退恢复。

独立 Graph 位于 `/{locale}/graph/`，主导航、首页探索与所有实体阅读器均有入口；旧关联页继续保留并可携带查询进入全图。索引去重稳定实体 ID 与完全相同的关系，保留不同角色、曲目编号及日期。无关联实体仍进入布局，缺失端点不被创建为新实体。全图、节点类型、关系类型和一至三层周边共用数据；搜索只定位节点，不裁掉图谱。事件节点属于可选的时间轴引用，不能当作新百科实体计数。

Canvas 绘制全部有效节点和边，布局使用组件分组与 Barnes–Hut 计算，优先在浏览器后台线程中运行；不支持时分批本机计算。过滤后的布局任务替换旧任务，旧响应不能覆盖新视图。节点详情和路径保留文字依据，目录提供键盘入口。最短替代路径使用有界的 Yen 查询，展示至多三条无重复节点的较短路径；节点相同而关系不同的路线分开，不宣称穷举全部路径。查询应用类型、关系和事件条件，局部视图不限制路径查询；点击路径的图中查看会回到全图并缩放至路径。布局位置与缩放属于当前会话，地址保存筛选、中心、起终点及事件开关。

资料完善看板位于 `/{locale}/contribute/missing/`，与阅读器及 `missing-data.json` 共用 `entityCompleteness` 的字段规则。可按类型、缺失字段、名称与别名组合筛选，每次显示 24 条，并通过实际源文件路径打开编辑器。译文回退单独标记，不影响元数据分数；繁体中文不被当作缺少独立译文。演出类型需要曲目列表，展览与一般活动不被分配演出曲目任务；占位图片不算已填写配图。补充仍须走现有审核、合并与发布流程。

## 演出曲目与署名索引

演出档案读取统一实体的 `live-event`，主要出演与嘉宾来自显式字段，不展开组合成员。日期范围按原始精度展示，跨年范围参与覆盖年份的筛选；活动记录数量不等于独立公演场次。`setlist` 按源数组顺序展示并保留重复演唱与返场编号，标题自由填写；只有有效 `songId` 会形成歌曲链接及反向演出历史。没有编号时不捏造编号，最早已收录记录不认定为首次演唱。

署名索引只读取歌曲的 `credits`。关联实体按稳定 ID 编组，只有姓名的记录按明确填写的姓名单独编组，不自动匹配或合并到实体。同曲多角色仅计一首合作作品；“创作者 + 角色”必须匹配同一署名行。合作艺人来自显式演唱者，发行年份来自歌曲日期，概况按该署名全部已记录作品统计，筛选仅缩小下方作品列表。新记录经现有审核流程公开后随构建进入两个索引。

## Discovery 推荐与每日路线

入口为 `/{locale}/explore/discovery/`。使用统一实体、显式关系和可选时间轴，最多选择三位艺人／创作者或一个起点，以直接及两步连接筛选候选；标签、内容类型、元数据关键词和年份范围继续组合。没有日期的档案不参与已知年份匹配，跨年活动按记录范围匹配。艺人标签不传给歌曲，组合身份不推断演出。排序兼顾连接距离与内容类型，并逐项显示依据。

默认每日路线按 UTC 更新，长度为三／五／七站，采用可复现的日期与变体顺序；语言和链接路径不改变身份及路线顺序。路线从符合偏好的线索或用户起点出发，后续只能沿明确关系移动，允许跨类型和年份，不重复节点、不补假连接。孤立节点显示单站，短路线显示实际终点。地址保存已应用条件、日期、变体与当前站点；分享固定日期，普通今日页面在 UTC 跨日后更新，未应用修改不被站点导航覆盖。

公开文章索引仅无凭据读取公开列表，限制总读取时间与分页规模，只保存标题、简介、记录日期和关联 ID；正文、账户与非公开状态不进入快照。文章使用独立命名空间防止 ID 碰撞，只有已存在的关联 ID 形成边，标题不用于推断关系。文章读取失败保留其他实体推荐并标记收录不完整。当前文章阅读继续使用既有服务，不将本机快照或模拟数据当作文章投稿、审核或权限验收。

推荐与路线共用 `discovery-catalog.json`。更新元数据后重新构建，检查新字段的来源、匿名空结果、分享复现、UTC 日期更新、五种语言、无脚本首屏和既有 Graph／演出／署名入口。风格覆盖少时保留如实的空结果与主动放宽条件入口，不自动改写标签。

## 图库与文章

图库资料变更通过[设定投稿流程](../manuals/contribute/gallery/zh.md)审核后才显示在公开页面；新增可选角色须更新实体，并检查前台选择器与图库目录。

文章使用独立投稿页面，经审核后才公开，不通过百科 GitHub PR，见[文章投稿说明](../manuals/contribute/article/zh.md)。正文与来源许可需要单独核对，不能以图片上传或实体关联代替出处。

## 发布前检查

先验证内容与文档镜像，再构建。人工检查本次影响的入口、选择器、阅读器目录与背景、跨条目跳转、手机布局。投稿、附件和图库须分别记录真实流程证据；仅看到图片或模拟响应不能证明上传审核流程已通过。

## Story Mode

`storyRoutes.mjs`定义学习目的、提问、建议时长与选材规则，`storyCatalog.mjs`在构建时解析当前实体、明确关系、Chronicle 和既有世界观入口。导览的独立选材不是事实关联；歌曲与创作者只能沿已记载演唱／制作署名，演出只选演唱会类型。缺少材料时显示真实缺项，不用相似名字或搜索结果补造连接。

媒体来自结构化字段或正文明确媒体指令／视频链接，排除代码与注释；客户端仅收到目标与显示文案，不接收完整正文。播放器按需加载，换章关闭，原链接保留。世界观摘要默认折叠。

`storyProgress.mjs`保存路线指纹、稳定章节 ID 与显式完成的章节，存储键为 `kamitsubaki.story-progress.v1`。五种语言共用进度；选材身份或媒体变化会使旧指纹失效。分享不携带已读数据，不读取账户、收藏或浏览历史；存储失败和脚本失败都保留阅读能力。
