## 変更前の準備

問題を再現し、URL、言語、画面幅、テーマ、データ取得元を記録します。タスク専用の隔離環境で一覧、詳細、操作、再読み込み後の状態を確認し、本番のアカウントや記録を使いません。

## 活動センター

入口は `/{locale}/events/` で、観測者企画が既定です。`?source=official` で公式に切り替えます。旧入口は互換性を保ちます。種類、月、表示、絞り込み、日付は URL に保存し、更新・共有後も復元できることを確認します。

カレンダーは FullCalendar の標準プラグイン、地域選択は Tom Select、浮層は Floating UI、ポスターは PhotoSwipe を使います。日をまたぐイベント、追加表示、空状態、失敗を確認します。終日は時差変換せず、終了不明の時間を補わず、日付未定の活動には位置指定や単独のカレンダーファイルを生成しません。

公開データは `/api/activity-center` から読みます。デスクトップは月表示、スマートフォンは一覧が既定で、絞り込みは同じフォーム状態を使います。ポスター全体を表示し、画像なしでも説明と詳細導線を残します。共有文に統計用の入口パラメーターを含めません。

## 観測パネルとお知らせ

BaseLayout は総覧、お知らせ、AI、ツールを持つ ObserverDashboard を一つだけ配置します。支援入口は独立です。企画と公式を分け、表示・クリックを参加申込と解釈しません。

お知らせは `src/content/announcements` にあり、translationKey、pinned、autoOpen、order を使います。`reminderVersion` は重要な修訂で再通知が必要なときだけ増やします。誤字修正や言語切り替えで繰り返し通知しません。

AI は最初の選択時に読み込みます。区域の切り替え・閉じる操作では下書きとリクエストを保持し、アカウント変更時は旧リクエストと会話を破棄します。Esc、背景の隔離、閉じた後のフォーカス、JavaScript なしの入口を確認します。

## 記事リーダー

`articleReaderPresentation.mjs` はクライアントと Pages Function で共有し、初回と更新後の表示をそろえます。author は元の署名を保持し、アバターは既存のアカウント対応から取得します。不足・不正な画像は既存アイコンにし、ニックネームから本人を推測しません。

更新失敗時もタイトルと本文を残し、再試行できます。目次やクリック処理を重複させません。関連記事は明示された関連 ID に基づき、本文リンクと区別します。

## エディターと発言ブロック

百科と記事は `prototypes/novel-editor` を共有します。挿入メニュー、属性、ソース、プレビューの往復を保ちます。発言者は発言の編集画面で管理し、アバター、色、項目の関連付けは任意で、文書の著者とは別です。

一括取り込みでは先にプレビューし、発言者のない段落は通常の本文として残します。挿入は取り消せるため、重複確認を追加しません。原文、出典、未知の構文を保ちます。操作は[構文ガイド](/ja/docs/contribute/syntax/)を参照してください。

## 結果と制約

読み込み、空状態、失敗、復旧、スマートフォンのフォーカスを確認します。機能名でテストを探し、[検証と公開](/ja/docs/develop/operations/)の全体チェックも実行します。ローカルの模擬結果は実プロバイダー、本番権限、公開成功の証拠にはなりません。
