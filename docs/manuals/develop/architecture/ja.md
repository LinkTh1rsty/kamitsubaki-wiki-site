## 入口から動作を追う

主サイトは Astro で静的ページを生成します。ルートは `src/pages`、コンポーネントは `src/components`、共通ルールは `src/lib`、ビルドと検証は `scripts` にあります。まず現在のルートを特定し、コンポーネント、データ取得、スタイルを追ってください。旧設計から実装を推測しません。

百科の Markdown は `src/content`、年表イベントは `src/data/chronicle` にあります。記事・画像には動的サービスとの境界があり、公開内容と非公開の下書きは別のデータです。

## エディターと影像館

`prototypes/novel-editor` は正式な共通エディターのソースです。主サイトの `build:editor` が子パッケージをインストール・ビルドし、静的リソースに出力します。生成済みファイルを直接編集しません。

`prototypes/chronoframe-explore` は独立した影像館サービスです。そのディレクトリの README に従って設定します。Wiki とランタイム、データベース、公開手順を共有するとは限りません。

## API と本人確認の境界

公開ページは必要な公開フィールドだけを読みます。下書き、審査の会話、アカウント操作はサーバー側の権限に依存し、ボタンを隠すだけでは権限制御になりません。アカウント UI は Wiki ドメインに置き、戻り先は厳密な接続先レジストリに従います。

共通のアカウント導線や画像 UI を変えた場合は両方を確認します。既存のユーザー ID、連携、コールバックを保ち、設定の問題を避けるために本人確認や Passkey を作り直さないでください。

## 変更前後の確認

現在のルート、クエリ、データ取得元、状態遷移を記録してから最小限の変更を行います。初回表示、再読み込み、失敗後の再試行、旧リンクを確認し、静的ビルド、ローカルの模擬結果、実サービスの結果を区別します。
