## 状況を残す

URL、コミット、言語、操作、期待と実際の結果、最初のエラーを記録します。未送信の本文や下書きを保存してから環境を調べます。内容削除、他の作業ツリーのリセット、アカウント初期化から始めません。

## ランタイムとインストール

`node --version`、`pnpm --version`、`pnpm node:check` を実行します。`.node-version` に合わせ、`pnpm install --frozen-lockfile` を使います。ロックファイルの問題はブランチと依存変更を確認し、無条件で再生成しません。

エディターの失敗は子パッケージのインストール・ビルドの最初のエラーを確認します。生成ディレクトリではなく正式ソースを修正します。

## 起動と API

自分の別プロセスがポートを使っていないか確認し、タスクに空きポートを選びます。他タスクのサービスを停止しません。連携エラーは全ローカル接続先と API 設定の一致を確認してから、サービス起動を確認します。

隔離モードでの外部画像、フォント、プロバイダー制限はデータ破損とは限りません。ローカル例で UI を確認し、実サービスの接続確認とは分けます。

## コンテンツ、翻訳、リンク

`pnpm validate:content` の最初の報告から、種類、必須フィールド、安定 ID、関連先を確認します。`pnpm docs:check` で欠けた言語、順序、リンクを特定します。

繁体字が古い場合は簡体字の元稿を直し、`pnpm i18n:generate` を実行します。日本語と英語には独立した本文が必要です。言語切り替えが誤る場合は章の識別子と翻訳 URL を確認します。

ビルド後のリンクは `node scripts/v3/check-built-links.mjs` で調べます。旧入口の転送を保ち、消失した内容を隠すためにリンクを削除しません。

## 画像と検索

原画像 URL、権限、使用根拠を確認し、サムネイルと通信を調べます。ローカル画像変更後は `pnpm images:generate` を実行し、原画像を上書きしません。画像なしでも文章を残します。

文書検索は現在の言語の正式な章だけが対象です。短いタイトル・本文の語句を試します。索引失敗時は同じ言語の docs/search-index.json を確認して再試行します。歴史的アーカイブは検索されません。

## 下書きと公開状態

ローカル保存、クラウド下書き、提出済み、承認済み、公開版は別の状態です。元の投稿記録で応答、競合、差し戻しを確認し、重複稿で回避しません。手順は[審査ガイド](/ja/docs/contribute/review/)を参照してください。

解決しなければ再現手順、環境、エラー、確認済み事項を添えます。本番 Cookie、認証情報、非公開本文、他人の記録を含めないでください。
