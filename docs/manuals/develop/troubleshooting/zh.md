## 先保存现场

记录 URL、提交、语言、操作、预期与实际结果，保留首个终端或网络错误。保存未提交正文或导出草稿，再处理环境。不要先删除内容、重置其他工作树或清空账号来“重试”。

## 运行时或安装失败

运行 `node --version`、`pnpm --version` 和 `pnpm node:check`。版本必须符合 `.node-version`，安装使用 `pnpm install --frozen-lockfile`。锁文件错误先核对分支与依赖变更，不随意重新生成锁文件。

编辑器构建失败时查看子包安装或构建的第一个错误；修改正式编辑器源码，不编辑生成目录。

## 服务启动或接口错误

确认端口未被自己的另一个进程占用。给当前任务选择空闲端口，不结束其他任务的服务。跨服务错误先检查全部本机来源和 API 配置是否一致，再核对服务是否启动。

隔离模式的外部图片、字体和供应商受限不等于业务数据损坏。用本机样例确认界面，并把真实服务连通性留作独立证据。

## 内容、翻译或链接错误

字段错误从 `pnpm validate:content` 的第一条报告查起，核对实体类型、必填字段、稳定 ID 和关系目标。文档错误用 `pnpm docs:check` 定位缺失语言、排序或链接。

繁体不同步时先修改简中源，再运行 `pnpm i18n:generate`。日文和英文需维护独立正文。语言切换跳错页时核对章节标识与对应语言 URL。

构建成功但链接失效时运行 `node scripts/v3/check-built-links.mjs`。保留旧入口的跳转；不要通过删除链接掩盖丢失内容。

## 图片与搜索异常

图片先核对原图地址、权限和授权资料，再检查缩略图及控制台请求。更新本地图后运行 `pnpm images:generate`，不要覆盖原图。无图时仍须保留文字。

文档搜索只覆盖当前语言正式章节。先用较短的标题或正文关键词；索引加载失败时检查同语言的 docs/search-index.json 是否存在并重试。历史归档不会出现在结果中。

## 草稿和公开状态不同

本机保存、云端草稿、已提交、已批准和公开版本是不同状态。先在原投稿记录阅读回执、版本冲突或退回意见；不要新建重复稿来绕过错误。完整步骤见[投稿审核](/zh/docs/contribute/review/)。

仍不能解决时附上复现步骤、环境、错误和已做检查。不要附带生产 Cookie、凭据、私有正文或他人的记录。
