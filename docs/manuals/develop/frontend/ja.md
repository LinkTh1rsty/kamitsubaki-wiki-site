## 既存のページ構成を使う

通常のツール・投稿ページには `WorkspaceShell`、`WorkspaceHeader` とサイトナビゲーション、長い本文には `Reader` を使います。百科、記事、ガイドではレイアウトが異なるため、適切なモードを選び、全体の変更で他の読書画面を壊さないでください。

ドキュメントは独自レイアウトでサイトナビゲーション、フッター、ガイド用リーダーを再利用します。スタイルを文書領域に限定し、広い画面では章ナビと目次、スマートフォンでは展開できるナビを提供します。本文の閲覧は検索スクリプトに依存しません。

## ボタン、フォーム、アイコン

`WorkspaceButton` は `href` があればリンクになります。ボタンの既定 type は button なので、送信には `type="submit"` を指定します。標準の disabled、name、value とキーボード操作を保ちます。`WorkspaceControl` の select・textarea でもラベルを付けます。

エラーは `aria-invalid` と `aria-describedby` で説明に関連付けます。検証と状態管理はページ側に置きます。アイコンは `Icon` と既存の Lucide 素材を使い、アイコンのみのボタンには翻訳したアクセシブル名を付けます。

テーマと余白は既存 token を使います。共通コントロールの基礎スタイルを各ページに複製しません。

## 画像とメディア

`ResponsiveImage` を使い、実際の表示サイズを指定します。サムネイルは原画像とは別の表示用コピーで、原画像を上書きしません。`pnpm images:generate` で個別生成できます。生成 WebP、キャッシュ、ビルド出力は原稿としてコミットしません。

ポスターは全体表示を維持し、画像が失敗しても文章と操作を残します。外部メディアは制御された短縮構文を使い、生の iframe で置き換えません。

## Markdown の信頼境界

Markdown と HTML を解析して共通の安全フィルターを通し、許可されたメディアのプレースホルダーをプレイヤーに変換した後、サイトの変換処理を行います。未確認のタグを許可するために `wikiHtmlSchema` を迂回したり順序を変更しません。

新しい構文は編集、ソース、プレビュー、公開表示で確認します。詳しくは[構文とフィールド](/ja/docs/contribute/syntax/)を参照してください。

## 確認する

明暗テーマ、320px の画面、キーボード、動きの抑制、長いタイトル、通信失敗後の再試行を確認します。共通部品を変えたらアカウントと画像の入口も確認します。コマンドは[検証と公開](/ja/docs/develop/operations/)にあります。
