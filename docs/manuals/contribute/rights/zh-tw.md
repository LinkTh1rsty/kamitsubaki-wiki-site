## 事實與資料來源

優先使用官方公告、作品頁面、實體訪談等可追溯來源。寫清標題、釋出者、日期與可訪問連結；引用二手整理時標明其性質，不把推測寫成官方事實。修訂舊詞條時保留仍正確的原文，新增內容清楚分段，不為了統一口吻大段改寫。來源元件記錄事實依據，不等於文章與詞條之間的顯式關聯。

## 圖片與許可

上傳者應能說明圖片作者、出處與使用依據。相簿每套設定可填共用來源，單張圖片出處不同時在該圖片上覆蓋。詞條附件也需填寫來源；圖片上傳成功不意味著本站取得版權，也不意味著可以任意轉載。不要上傳含不應公開的個人資料或無法說明來源的素材。版權疑問可先閱讀[站點許可說明](/zh-tw/license/)並聯系維護者核對。

## 語言版本

簡中、日文、英文分別維護，詞條跨語言共用穩定 ID 和結構化身份欄位。繁體臺灣與香港版本由簡中生成，不直接編輯派生檔案。翻譯不能只換標題而留下大量另一語言正文，也不能因缺譯而偽裝已完成。文章在實際撰寫的內容語言下投稿；需要另一語言版本時按相應語言另行準備並核對事實。時間軸事件和相簿資料依其內容模型關聯實體，不會因為正文提到角色或日期就自動建立記錄。

## 許可判定與欄位例項

### 預設規則

- 除另有標註外，本站**有權許可的原創文字**採用 [CC BY-NC-SA 4.0 國際許可協議](https://creativecommons.org/licenses/by-nc-sa/4.0/)。
- 圖片、封面、歌詞、音影片、角色設計、Logo、商標及其他第三方素材不屬於預設文字許可，相關權利歸原權利人。
- 來自其他站點或作者的文字繼續遵守原協議。許可標記不能代替轉載許可，也不能讓無權使用的內容變得可以使用。
- 程式程式碼和倉庫軟體檔案不在上述 CC 內容許可範圍內；倉庫根目錄不會用內容協議建立 `LICENSE`。
- 貢獻入口目前不取得統一的 CC 授權。其他貢獻者的文字只有在權利人另行明確同意，或條目記錄了相應許可時，才能納入 CC BY-NC-SA 4.0。

## 條目許可欄位

藝人、企劃、日誌、歌曲和專輯條目可以在 YAML frontmatter 中新增 `license`：

| `code` | 用途 |
| --- | --- |
| `CC-BY-NC-SA-4.0` | 明確標記本站有權許可的原創文字 |
| `CC-BY-NC-SA-3.0-CN` | 採用 3.0 中國大陸版協議的第三方文字或其翻譯、改編 |
| `rights-reserved` | 原權利人保留權利，不適用本站預設 CC 協議 |
| `authorized-use` | 僅按權利人的特定授權在本站使用 |

未知 `code` 會在 `pnpm check` 或構建時失敗。

### 本站原創文字

沒有 `license` 欄位時，頁面顯示經過權利範圍限定的預設 4.0 宣告。需要顯式記錄時可以寫：

```yaml
license:
  code: "CC-BY-NC-SA-4.0"
  attribution: "本站原创作者"
```

### 採用舊版本 CC 協議的第三方文字

複製、翻譯、改寫或合併採用 3.0 CN 的第三方文字時，必須保留原許可版本，並填寫來源、署名和修改說明：

```yaml
license:
  code: "CC-BY-NC-SA-3.0-CN"
  attribution: "原作者与贡献者"
  sourceTitle: "原始条目标题"
  sourceUrl: "https://example.com/original-entry"
  modifications: "基于原条目进行整理、改写并补充来源。"
```

使用 `CC-BY-NC-SA-3.0-CN` 時，應填寫 `attribution`、`sourceTitle`、`sourceUrl` 和 `modifications`，供稽核者核對原許可與改動；當前基礎 schema 只限定許可程式碼，不能替代人工許可稽核。三語翻譯如果源自同一份第三方文字，也必須在各語言檔案中保留該標記。

### 保留權利與特定授權

```yaml
license:
  code: "rights-reserved"
  attribution: "原作者或权利人名称"
  sourceTitle: "作品名称"
  sourceUrl: "https://example.com/original"
  note: "著作权由原作者保留。"
```

```yaml
license:
  code: "authorized-use"
  attribution: "权利人名称"
  note: "依据权利人许可，仅限本站使用。"
```

只有確實取得授權時才能使用 `authorized-use`。使用 `rights-reserved` 也不代表本站自動獲得複製權；沒有合法使用依據的材料不應提交。

## 圖片與其他媒體

詳情頁會統一顯示媒體排除宣告，因此條目有官方封面或藝人圖時，不要僅因為圖片而把整篇文字標為 `rights-reserved`。文字許可與媒體權利分別判斷：

- 優先使用官方公開頁面、正規發行平臺或已獲授權的素材。
- 在正文“來源”中保留素材出處，PR 中說明圖片來源和使用依據。
- 不上傳來源不明、移除水印、人工放大或明顯超出百科介紹需要的素材。

## 相簿逐圖核對

[直接上傳照片](/zh-tw/gallery/manage/photos/)即使不分類，也必須逐圖說明**作者、出處和使用依據**。一批照片可以共用資料；攝影者或來源不同的照片要單獨覆蓋。官方公開素材須給出原頁面連結；已獲授權須說明授權範圍。只在詞條或文章中出現過的舊圖會先進入後臺待核對佇列，不會因掃描到檔案就自動成為相簿公開圖片。稽核者確認來源與使用依據後，才會把它納入圖片檔案。

## Review 檢查

- 這是原創文字、獲得授權的文字，還是第三方協議內容？
- 許可版本是否與原來源完全一致？
- 是否提供原頁面、署名和修改說明？
- 圖片、歌詞和嵌入媒體是否被誤認為預設 CC 文字內容？
- 三種語言是否使用一致的來源和許可邏輯？
- `pnpm test`、`pnpm check` 和 `pnpm build` 是否通過？

## 上傳表單的三種使用依據

| 選項 | 需要填寫 |
| --- | --- |
| 官方公開素材 | 原作者／官方署名、實際釋出者或作品名稱、原始釋出頁面 URL |
| 投稿者原創 | 確認你是原作者，填寫準確署名和出處名稱；可補充自己的原始釋出頁面 |
| 已獲授權 | 原作者與原始出處，以及許可範圍、授權日期或可核對的許可憑據 |

使用依據預設留空。渠道名稱候選不代表本站驗證了授權，官方公開也不是通用轉載許可。共用資料適用於整批圖片；署名或許可不同的圖片必須單獨補充。資料不清楚時先儲存私有草稿，再核對來源，稽核者可逐圖退回要求補充。
