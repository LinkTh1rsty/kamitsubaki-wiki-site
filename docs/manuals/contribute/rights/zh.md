## 事实与资料来源

优先使用官方公告、作品页面、实体访谈等可追溯来源。写清标题、发布者、日期与可访问链接；引用二手整理时标明其性质，不把推测写成官方事实。修订旧词条时保留仍正确的原文，新增内容清楚分段，不为了统一口吻大段改写。来源组件记录事实依据，不等于文章与词条之间的显式关联。

## 图片与许可

上传者应能说明图片作者、出处与使用依据。图库每套设定可填共用来源，单张图片出处不同时在该图片上覆盖。词条附件也需填写来源；图片上传成功不意味着本站取得版权，也不意味着可以任意转载。不要上传含不应公开的个人资料或无法说明来源的素材。版权疑问可先阅读[站点许可说明](/zh/license/)并联系维护者核对。

## 语言版本

简中、日文、英文分别维护，词条跨语言共用稳定 ID 和结构化身份字段。繁体台湾与香港版本由简中生成，不直接编辑派生文件。翻译不能只换标题而留下大量另一语言正文，也不能因缺译而伪装已完成。文章在实际撰写的内容语言下投稿；需要另一语言版本时按相应语言另行准备并核对事实。时间轴事件和图库资料依其内容模型关联实体，不会因为正文提到角色或日期就自动建立记录。

## 许可判定与字段实例

### 默认规则

- 除另有标注外，本站**有权许可的原创文字**采用 [CC BY-NC-SA 4.0 国际许可协议](https://creativecommons.org/licenses/by-nc-sa/4.0/)。
- 图片、封面、歌词、音视频、角色设计、Logo、商标及其他第三方素材不属于默认文字许可，相关权利归原权利人。
- 来自其他站点或作者的文字继续遵守原协议。许可标记不能代替转载许可，也不能让无权使用的内容变得可以使用。
- 程序代码和仓库软件文件不在上述 CC 内容许可范围内；仓库根目录不会用内容协议创建 `LICENSE`。
- 贡献入口目前不取得统一的 CC 授权。其他贡献者的文字只有在权利人另行明确同意，或条目记录了相应许可时，才能纳入 CC BY-NC-SA 4.0。

## 条目许可字段

艺人、企划、日志、歌曲和专辑条目可以在 YAML frontmatter 中添加 `license`：

| `code` | 用途 |
| --- | --- |
| `CC-BY-NC-SA-4.0` | 明确标记本站有权许可的原创文字 |
| `CC-BY-NC-SA-3.0-CN` | 采用 3.0 中国大陆版协议的第三方文字或其翻译、改编 |
| `rights-reserved` | 原权利人保留权利，不适用本站默认 CC 协议 |
| `authorized-use` | 仅按权利人的特定授权在本站使用 |

未知 `code` 会在 `pnpm check` 或构建时失败。

### 本站原创文字

没有 `license` 字段时，页面显示经过权利范围限定的默认 4.0 声明。需要显式记录时可以写：

```yaml
license:
  code: "CC-BY-NC-SA-4.0"
  attribution: "本站原创作者"
```

### 采用旧版本 CC 协议的第三方文字

复制、翻译、改写或合并采用 3.0 CN 的第三方文字时，必须保留原许可版本，并填写来源、署名和修改说明：

```yaml
license:
  code: "CC-BY-NC-SA-3.0-CN"
  attribution: "原作者与贡献者"
  sourceTitle: "原始条目标题"
  sourceUrl: "https://example.com/original-entry"
  modifications: "基于原条目进行整理、改写并补充来源。"
```

使用 `CC-BY-NC-SA-3.0-CN` 时，应填写 `attribution`、`sourceTitle`、`sourceUrl` 和 `modifications`，供审核者核对原许可与改动；当前基础 schema 只限定许可代码，不能替代人工许可审核。三语翻译如果源自同一份第三方文字，也必须在各语言文件中保留该标记。

### 保留权利与特定授权

```yaml
license:
  code: "rights-reserved"
  attribution: "原作者或权利人名称"
  sourceTitle: "作品名称"
  sourceUrl: "https://example.com/original"
  note: "著作权由原作者保留。"
```

```yaml
license:
  code: "authorized-use"
  attribution: "权利人名称"
  note: "依据权利人许可，仅限本站使用。"
```

只有确实取得授权时才能使用 `authorized-use`。使用 `rights-reserved` 也不代表本站自动获得复制权；没有合法使用依据的材料不应提交。

## 图片与其他媒体

详情页会统一显示媒体排除声明，因此条目有官方封面或艺人图时，不要仅因为图片而把整篇文字标为 `rights-reserved`。文字许可与媒体权利分别判断：

- 优先使用官方公开页面、正规发行平台或已获授权的素材。
- 在正文“来源”中保留素材出处，PR 中说明图片来源和使用依据。
- 不上传来源不明、移除水印、人工放大或明显超出百科介绍需要的素材。

## 图库逐图核对

[直接上传照片](/zh/gallery/manage/photos/)即使不分类，也必须逐图说明**作者、出处和使用依据**。一批照片可以共用资料；摄影者或来源不同的照片要单独覆盖。官方公开素材须给出原页面链接；已获授权须说明授权范围。只在词条或文章中出现过的旧图会先进入后台待核对队列，不会因扫描到文件就自动成为图库公开图片。审核者确认来源与使用依据后，才会把它纳入图片档案。

## Review 检查

- 这是原创文字、获得授权的文字，还是第三方协议内容？
- 许可版本是否与原来源完全一致？
- 是否提供原页面、署名和修改说明？
- 图片、歌词和嵌入媒体是否被误认为默认 CC 文字内容？
- 三种语言是否使用一致的来源和许可逻辑？
- `pnpm test`、`pnpm check` 和 `pnpm build` 是否通过？

## 上传表单的三种使用依据

| 选项 | 需要填写 |
| --- | --- |
| 官方公开素材 | 原作者／官方署名、实际发布者或作品名称、原始发布页面 URL |
| 投稿者原创 | 确认你是原作者，填写准确署名和出处名称；可补充自己的原始发布页面 |
| 已获授权 | 原作者与原始出处，以及许可范围、授权日期或可核对的许可凭据 |

使用依据默认留空。渠道名称候选不代表本站验证了授权，官方公开也不是通用转载许可。共用资料适用于整批图片；署名或许可不同的图片必须单独补充。资料不清楚时先保存私有草稿，再核对来源，审核者可逐图退回要求补充。
