## 先选择任务

在[参与共建](/zh/contribute/)选择：修改或新建**百科词条**、撰写**文章**、[上传独立照片或设定组](/zh/gallery/manage/)，或[投稿时间轴事件](/zh/chronicle/submit/)。词条与时间轴由 GitHub PR 承载提案；文章可保存云端草稿；图库图片先私有暂存，再逐图提交审核。人物、图片类型和设定组可以暂不填写，公开后再提出分类建议。投稿需要登录，公开前由维护者审核；各自的保存状态与公开条件不同。

## 开始前核对

先搜索是否已经存在目标词条、文章或设定，核对语言、别名及团体层级；准备原始来源、作者、日期和图片使用依据。纠错时保留原本有效的正文，只增补或订正有依据的内容。把事实、推测和个人观点分清：事实写入词条并注明来源，论述可写成文章。

## 保存不等于投稿

编辑器可能显示**本机草稿**或**云端草稿**；图库还会显示**待上传、上传中、已暂存**。只有点击对应的“提交审核”并收到带记录编号的回执，才算进入审核队列。请从回执打开[创作者中心](/zh/account/creator/)确认记录与状态。网络失败时先看是否已有记录，避免重复创建。

<a id="site-route"></a>
## 路线一：在站内编辑

1. 在[投稿选择页](/zh/contribute/)选一项任务。词条从现有词条的编辑入口载入原文；文章从空白稿或已有文章继续；图库可先直接上传照片，或选择角色创建设定组；时间轴从[事件列表](/zh/chronicle/?view=list)选择修订，或直接新建。
2. 核对语言和已有内容，只改有依据的部分。准备标题、日期、来源网址；图库还要准备图片使用依据。时间轴的“年”“月”“日”精度必须与实际资料一致，不知道具体日期就选年或月。
3. 保存草稿并查看预览。**本机草稿只在当前浏览器**；云端草稿绑定账号。图库的“已暂存”只代表文件已私有上传，其他人还看不到。
4. 点击“提交审核”，等待记录编号。到[创作者中心](/zh/account/creator/)查看状态、维护者意见和唯一的下一步操作。词条及时间轴的 PR 可以从记录详情打开。
5. 审核退回时按照意见修改同一份投稿；审核通过或 PR 合并后仍可能显示“待网站发布”。只有公开页面和记录状态都确认后，内容才算可供读者查看。

**遇到失败：** 保存失败时先复制或保留本机稿；提交超时后先检查创作者中心是否已有记录；提示原文件冲突时重新读取当前版本，逐项核对差异，再重投。不要为了消除冲突直接覆盖他人的修改。

<a id="github-route"></a>
## 路线二：在 GitHub 投稿

1. 在网站找到目标词条，打开“编辑源文件”；或到仓库中定位对应的 `src/content/.../zh.md`、`ja.md`、`en.md`。时间轴现有事件在 `src/data/chronicle/<年份>.yml`，新事件使用独立文件 `src/data/chronicle/<年份>/event-<编号>.yml`。
2. Fork 仓库或建立自己的分支。编辑前阅读[字段与语法说明](/zh/docs/contribute/syntax/)和[内容与格式指南](/zh/docs/contribute/format/)；只修改目标内容，并保留 ID、语言、来源及现有有效段落。
3. 在本地或 GitHub 预览变更，检查链接、日期、图片路径和 YAML 格式。提交 commit，向主分支创建 Pull Request，说明修改范围、资料来源及你已做的检查。
4. 在 PR 中回应维护者的审阅意见，继续向同一分支推送修订。维护者合并后等待网站构建与发布，再打开公开页面核对。GitHub 路线的进度以 PR 为准，可能不会自动出现于站内创作者中心。

**遇到失败：** 不知道字段怎么写时先看相同类型的已有文件；构建失败时读 PR 检查日志；遇到合并冲突先更新主分支并逐段核对。不要只因为检查通过就写“已公开”。

## AI 可以怎样帮你

把你已有的来源和草稿交给 AI，让它**整理结构、解释字段或指出待核对处**。例如：

> 请只根据我下面提供的资料，把这条时间轴事件整理成“标题、日期及其精度、摘要、关联词条、来源”五栏。资料没有写出的日期或人物请标为“待核对”，不要猜测，也不要添加我未提供的事实。资料：[粘贴原始来源与摘录]

将结果与原始来源逐项对照，再录入编辑器或 GitHub。AI 回答不能替代来源；歌词、译文、图片授权和时间戳尤其需要人工核对。处理同步歌词时可参考[旧版保留的 AI 排版提示词](/zh/docs/contribute/syntax/#ai-lyrics-html)。
