> 新流程隨上傳與文章工作臺更新一同啟用。維護者應先完成配套後端的增量資料庫遷移，再發布前端和本說明；私有暫存已上傳不等於已公開，仍須明確提交並通過審核。

## 建立或修改

從[文章專欄](/zh-tw/articles/)進入[投稿頁](/zh-tw/articles/submit/)。修改已公開文章時，從其閱讀頁進入提交修改，先核對當前公開版本。文章沿用詞條的正文編輯工作臺，但**文章不走 GitHub PR**：雲端草稿、提案及公開版本由站點分別展示。

閱讀頁僅向有編輯許可權的人顯示該文章的修改入口；其他讀者看到“投稿文章”，用於建立自己的新文章，不會修改正在閱讀的文章。

## 填寫與儲存

填寫標題、內容語言、分類及正文；摘要和關聯詞條可選。文章可獨立發表，也可明確關聯多個詞條。關聯時選擇正確的穩定詞條 ID；正文裡的 WikiLink 或普通連結不會自動建立“相關文章”。選擇格式工具或原始碼模式撰寫，預覽標題、段落、圖片網址和閱讀目錄。使用“插入圖片”搜尋已公開相簿，或上傳新圖片到文章私有暫存區；填寫替代文字、圖片說明、作者、來源與使用依據。原有 Markdown 圖片語法仍可使用。

正文保留當前瀏覽器的本機編輯狀態；登入後輸入會防抖自動儲存雲端草稿。“本機”和“雲端”儲存狀態分別顯示，“儲存草稿”仍可手動同步。斷網時修改保留在本機，恢復連線後重試；離開前確認雲端已儲存。其他裝置登入同一賬號後，從創作者中心開啟草稿繼續。標題與正文須在提交稽核前完整；編輯器給出的問題應先定位並修正。

## 提交與審稿

點選“提交稽核”並等待回執，再到[創作者中心](/zh-tw/account/creator/)開啟對應記錄。稽核中或退回的新版本不會覆蓋現有公開文章；維護者批准後，新版本才在當前文章語言的專欄出現。退回時閱讀意見，修改後重新提交。若提示版本衝突，重新載入公開版本並對照自己的修改，不要讓舊草稿靜默覆蓋他人的已批准內容。

## 編輯器操作例項

例如要發表一篇不依附詞條的作品考證：選擇實際寫作語言和文章分類，填寫標題、摘要與正文，**關聯詞條留空**。若文章同時討論兩首歌曲，則在屬性中明確選擇兩首歌曲的穩定 ID；正文中的 `[[词条]]` 只提供閱讀連結，不會把文章加入兩首歌曲的“相關文章”。儲存草稿後重新整理，先從創作者中心確認雲端版本，再提交稽核。

正文與詞條共用視覺化編輯器：標題和分類在屬性中，文章原始碼模式只處理正文。編輯長文時用大綱定位段落，用預覽核對標題、目錄、連結與圖片。從公開相簿選擇的圖片複用已有媒體；新圖先私有暫存，服務端確認後插入穩定引用。稽核批准並完成圖片公開同步後，公開文章使用有效圖片連結。私有預覽僅供本人和稽核者檢視；別把本地 `blob:` 預覽地址寫進正文。

## 修改公開文章與衝突

從公開文章發起修改時，編輯器以當前已批准版本為基準。待審修訂只對投稿者和稽核者可見；讀者繼續看到舊公開版。若其他修訂先獲批准，舊基準的提交會產生版本衝突，應先比對新舊內容再重投。退回稿在原記錄中閱讀意見，修改同一文稿，不另建一篇同標題文章。

## 公開前檢查

確認標題和正文完整、分類與內容相符、摘要不冒充事實來源、每張圖片有可用地址和使用依據、關聯 ID 對應正確詞條。提交後通過回執進入記錄，等待稽核；只有公開閱讀頁能開啟新版本，才算真正釋出。

## 兩個視窗和圖片釋出失敗

另一視窗儲存了同一篇草稿時，自動儲存暫停並展示本機／雲端對比。可將本機內容另存為提案，或載入雲端版；載入前會保留本機備份。不要用重複點選繞過沖突。來源與授權未完成的新圖可以保留在私有草稿中，提交前必須補齊。圖片公開同步失敗時不會把含有失效新圖的文章切換為公開版本；在稽核記錄核對結果後由維護者重試。

新圖選中後開始私有暫存。尚未插入正文的圖片資料和失敗恢復記錄儲存在當前裝置；換裝置繼續前，先補齊資料、插入正文並確認雲端已儲存。選用已公開圖片時只需修改替代文字和圖片說明，原稽核來源與使用依據保持不變。
