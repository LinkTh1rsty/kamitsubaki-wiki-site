> 新流程随上传与文章工作台更新一同启用。维护者应先完成配套后端的增量迁移，再发布前端和本说明；私有暂存已上传不等于已公开，仍须明确提交并通过审核。

## 创建或修改

从[文章专栏](/zh/articles/)进入[投稿页](/zh/articles/submit/)。修改已公开文章时，从其阅读页进入提交修改，先核对当前公开版本。文章沿用词条的正文编辑工作台，但**文章不走 GitHub PR**：云端草稿、提案及公开版本由站点分别展示。

阅读页仅向有编辑权限的人显示该文章的修改入口；其他读者看到“投稿文章”，用于创建自己的新文章，不会修改正在阅读的文章。

## 填写与保存

填写标题、内容语言、分类及正文；摘要和关联词条可选。文章可独立发表，也可明确关联多个词条。关联时选择正确的稳定词条 ID；正文里的 WikiLink 或普通链接不会自动建立“相关文章”。选择格式工具或源码模式撰写，预览标题、段落、图片网址和阅读目录。使用“插入图片”搜索已公开图库，或上传新图片到文章私有暂存区；填写替代文字、图片说明、作者、来源与使用依据。原有 Markdown 图片语法仍可使用。

正文保留当前浏览器的本机编辑状态；登录后输入会防抖自动保存云端草稿。“本机”和“云端”保存状态分别显示，“保存草稿”仍可手动同步。断网时修改保留在本机，恢复连接后重试；离开前确认云端已保存。其他设备登录同一账号后，从创作者中心打开草稿继续。标题与正文须在提交审核前完整；编辑器给出的问题应先定位并修正。

## 提交与审稿

点击“提交审核”并等待回执，再到[创作者中心](/zh/account/creator/)打开对应记录。审核中或退回的新版本不会覆盖现有公开文章；维护者批准后，新版本才在当前文章语言的专栏出现。退回时阅读意见，修改后重新提交。若提示版本冲突，重新载入公开版本并对照自己的修改，不要让旧草稿静默覆盖他人的已批准内容。

## 编辑器操作实例

例如要发表一篇不依附词条的作品考证：选择实际写作语言和文章分类，填写标题、摘要与正文，**关联词条留空**。若文章同时讨论两首歌曲，则在属性中明确选择两首歌曲的稳定 ID；正文中的 `[[词条]]` 只提供阅读链接，不会把文章加入两首歌曲的“相关文章”。保存草稿后刷新，先从创作者中心确认云端版本，再提交审核。

正文与词条共用可视化编辑器：标题和分类在属性中，文章源码模式只处理正文。编辑长文时用大纲定位段落，用预览核对标题、目录、链接与图片。从公开图库选择的图片复用已有媒体；新图先私有暂存，服务端确认后插入稳定引用。审核批准并完成图片公开同步后，公开文章使用有效图片链接。私有预览仅供本人和审核者查看；别把本地 `blob:` 预览地址写进正文。

## 修改公开文章与冲突

从公开文章发起修改时，编辑器以当前已批准版本为基准。待审修订只对投稿者和审核者可见；读者继续看到旧公开版。若其他修订先获批准，旧基准的提交会产生版本冲突，应先比对新旧内容再重投。退回稿在原记录中阅读意见，修改同一文稿，不另建一篇同标题文章。

## 公开前检查

确认标题和正文完整、分类与内容相符、摘要不冒充事实来源、每张图片有可用地址和使用依据、关联 ID 对应正确词条。提交后通过回执进入记录，等待审核；只有公开阅读页能打开新版本，才算真正发布。

## 两个窗口和图片发布失败

另一窗口保存了同一篇草稿时，自动保存暂停并展示本机／云端对比。可将本机内容另存为提案，或载入云端版；载入前会保留本机备份。不要用重复点击绕过冲突。来源与授权未完成的新图可以保留在私有草稿中，提交前必须补齐。图片公开同步失败时不会把含有失效新图的文章切换为公开版本；在审核记录核对结果后由维护者重试。

新图选中后开始私有暂存。尚未插入正文的图片资料和失败恢复记录保存在当前设备；换设备继续前，先补齐资料、插入正文并确认云端已保存。选用已公开图片时只需修改替代文字和图片说明，原审核来源与使用依据保持不变。
