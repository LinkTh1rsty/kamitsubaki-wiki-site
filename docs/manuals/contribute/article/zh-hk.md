> 新流程隨上傳與文章工作台更新一同啟用。維護者應先完成配套後端的增量資料庫遷移，再發布前端和本說明；私有暫存已上傳不等於已公開，仍須明確提交並通過審核。

## 創建或修改

從[文章專欄](/zh-hk/articles/)進入[投稿頁](/zh-hk/articles/submit/)。修改已公開文章時，從其閲讀頁進入提交修改，先核對當前公開版本。文章沿用詞條的正文編輯工作台，但**文章不走 GitHub PR**：雲端草稿、提案及公開版本由站點分別展示。

閲讀頁僅向有編輯權限的人顯示該文章的修改入口；其他讀者看到“投稿文章”，用於創建自己的新文章，不會修改正在閲讀的文章。

## 填寫與保存

填寫標題、內容語言、分類及正文；摘要和關聯詞條可選。文章可獨立發表，也可明確關聯多個詞條。關聯時選擇正確的穩定詞條 ID；正文裏的 WikiLink 或普通鏈接不會自動建立“相關文章”。選擇格式工具或源碼模式撰寫，預覽標題、段落、圖片網址和閲讀目錄。使用“插入圖片”搜尋已公開圖庫，或上傳新圖片到文章私有暫存區；填寫替代文字、圖片説明、作者、來源與使用依據。原有 Markdown 圖片語法仍可使用。

正文保留當前瀏覽器的本機編輯狀態；登錄後輸入會防抖自動保存雲端草稿。“本機”和“雲端”保存狀態分別顯示，“保存草稿”仍可手動同步。斷網時修改保留在本機，恢復連接後重試；離開前確認雲端已保存。其他設備登錄同一賬號後，從創作者中心打開草稿繼續。標題與正文須在提交審核前完整；編輯器給出的問題應先定位並修正。

## 提交與審稿

點擊“提交審核”並等待回執，再到[創作者中心](/zh-hk/account/creator/)打開對應記錄。審核中或退回的新版本不會覆蓋現有公開文章；維護者批准後，新版本才在當前文章語言的專欄出現。退回時閲讀意見，修改後重新提交。若提示版本衝突，重新載入公開版本並對照自己的修改，不要讓舊草稿靜默覆蓋他人的已批准內容。

## 編輯器操作實例

例如要發表一篇不依附詞條的作品考證：選擇實際寫作語言和文章分類，填寫標題、摘要與正文，**關聯詞條留空**。若文章同時討論兩首歌曲，則在屬性中明確選擇兩首歌曲的穩定 ID；正文中的 `[[词条]]` 只提供閲讀鏈接，不會把文章加入兩首歌曲的“相關文章”。保存草稿後刷新，先從創作者中心確認雲端版本，再提交審核。

正文與詞條共用可視化編輯器：標題和分類在屬性中，文章源碼模式只處理正文。編輯長文時用大綱定位段落，用預覽核對標題、目錄、鏈接與圖片。從公開圖庫選擇的圖片複用已有媒體；新圖先私有暫存，服務端確認後插入穩定引用。審核批准並完成圖片公開同步後，公開文章使用有效圖片鏈接。私有預覽僅供本人和審核者查看；別把本地 `blob:` 預覽地址寫進正文。

## 修改公開文章與衝突

從公開文章發起修改時，編輯器以當前已批准版本為基準。待審修訂只對投稿者和審核者可見；讀者繼續看到舊公開版。若其他修訂先獲批准，舊基準的提交會產生版本衝突，應先比對新舊內容再重投。退回稿在原記錄中閲讀意見，修改同一文稿，不另建一篇同標題文章。

## 公開前檢查

確認標題和正文完整、分類與內容相符、摘要不冒充事實來源、每張圖片有可用地址和使用依據、關聯 ID 對應正確詞條。提交後通過回執進入記錄，等待審核；只有公開閲讀頁能打開新版本，才算真正發佈。

## 兩個窗口和圖片發佈失敗

另一窗口保存了同一篇草稿時，自動保存暫停並展示本機／雲端對比。可將本機內容另存為提案，或載入雲端版；載入前會保留本機備份。不要用重複點擊繞過沖突。來源與授權未完成的新圖可以保留在私有草稿中，提交前必須補齊。圖片公開同步失敗時不會把含有失效新圖的文章切換為公開版本；在審核記錄核對結果後由維護者重試。

新圖選中後開始私有暫存。尚未插入正文的圖片資料和失敗恢復記錄保存在當前設備；換設備繼續前，先補齊資料、插入正文並確認雲端已保存。選用已公開圖片時只需修改替代文字和圖片説明，原審核來源與使用依據保持不變。
