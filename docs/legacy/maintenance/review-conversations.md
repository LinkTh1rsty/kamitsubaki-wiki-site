# 投稿审查闭环

任务 `20261019-admin-experience-a1`，本地候选已完成实现与集成验证，未合并 main 或变更生产。

`/[locale]/contribute/review/` 是五语言的鉴权页面壳，查询参数 `id` 指定本人审查记录；旧投稿链接通过 `kind` 与 `resource` 解析。静态页面不含投稿正文和讨论，不进入索引。所有数据由 `/api/reviews/*` 使用普通 Wiki 会话按实时业务归属授权，私有请求使用 no-store；账号切换清除当前内容。

文章被请求修改或撤回后，从审查页返回原 Novel 写作工作台。检查页用当前完整正文创建修改稿，保留图片资料、表格、注音、折叠内容及元数据；保存回执更新稳定的 revision 链接，同版本本地修改在刷新后保留。`parentRevisionId` 由服务端校验账号、原文章和语言，正式提交才进入原记录的新轮次，旧修订保持只读。提交后可直接回到本人审查记录。

图片、设定组、活动、词条和年表链接回原领域编辑器，继续使用原版本、权限和提交链路。词条和年表仍通过真实 GitHub PR 评审和合并，站内评论不自动转发到 GitHub。讨论回复在创作者中心提示，打开对应审查记录后标为已读。

## 交互与状态反馈

网站投稿流转、创作者中心，以及编辑器保存状态、属性、来源和审核操作复用小问号说明。点击或键盘激活可查看，Esc 关闭；正文表单继续保留辅助说明关联。帮助弹层须在手机视口内显示，窗口缩放或滚动后重新定位。

写作工作台的返回网站、投稿记录与账号入口并入现有侧栏和手机文档菜单。刷新、成功和失败反馈占用固定状态行；有内容时后台重读不再插入额外加载块。文章结果刷新同时更新列表、详情与当前绑定；词条的“查看最新结果”和“刷新状态”调用核对接口，以获取 PR 合并或上线后的结果。

本人审查页即使尚无讨论，也可以直接给维护者留言。编辑中再次输入的文字不能被前一次异步回复的成功回执清空。重投后的旧文章轮次保留在全部投稿中，并标为历史稿件，不再计入待处理事项。
